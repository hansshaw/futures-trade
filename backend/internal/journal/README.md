# 复盘日记与整理服务

`Open(path, analysis.Config)` 返回 `*Service`，`Register(mux, onChange)` 注册 API，生命周期结束调用 `Close()`。服务必须放在主服务认证中间件内；附件走带认证的 JSON API，不提供静态文件地址。`VisionEnabled()` 反映启动时的 `LLM_VISION_ENABLED=true` 配置。

## 数据与审计

- 日记、图片字节、复盘结果、输入快照、已采纳经验存入独立 bbolt；新建目录为 `0700`，数据库文件为 `0600`。这是文件访问权限保护，**不是数据库加密**。备份主数据库时应同时备份 `.journal.db`；不要在数据库写入时直接复制文件，应停止服务后复制，或使用 bbolt 一致性快照。
- 日记写入必须匹配当前 `revision`，冲突返回 HTTP 409；归档可恢复。日期允许提前计划。纪律自评为 0–5 的整数，其中 0 表示未评分。盈亏允许缺省，不把缺省当作 0。
- 每个正文字段最多 12,000 UTF-8 字节；最多 20 个标签、每篇 6 张截图。附件仅接受真正可完整解码的 PNG、JPEG、WebP；每张最多 4 MiB、24,000,000 像素。文件名只作为显示名称，数据库使用服务端随机 ID，不使用上传路径。
- 从日记移除附件只解除关联，不物理删除已上传图片；整理历史和快照也保留，以免旧结论失去可核对的原始资料。本版没有自动清理或永久删除功能，长期使用应规划磁盘空间和备份。
- 一次整理最多 20 篇。规则或模型只读取同一事务中的输入快照；结果单独存储，不更新日记版本或覆盖日记文字。每个结果保留输入版本、SHA-256 和引用的已采纳经验 ID。`GET /api/journal-reviews/{id}/snapshot` 可以读取当时的完整输入，与之后编辑的日记区别开。
- AI 结果始终为候选，用户单独点击采纳后才写入经验库；重复采纳幂等。最多 30 条最近采纳经验进入后续上下文，可通过 `use_accepted_lessons:false` 禁用。经验带原始 `review_id`、`evidence_ids`，不是不可质疑的事实，也不修改模型权重。
- `POST /api/journal-lessons/{id}/revoke`，正文 `{}`，可撤回错误经验。撤回和原报告候选状态恢复在同一事务中完成；重复撤回幂等，之后的新复盘不再引用这条经验。过去报告的输入快照保持当时内容，正在进行的整理也保留启动时的快照。撤回后可再次采纳。

## 模型边界

沿用 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`，调用兼容 Chat Completions 的 `/chat/completions`。使用 JSON 输出模式；输出字段、长度、完成状态及引用 ID 均验证，拒绝截断、未知字段、引用未选日记及多 JSON 对象。错误或超时不保存新报告，也不改动已有数据。文本证据是否真正支持结论仍须用户核验，ID 校验不能消除模型幻觉。

模型无工具、交易、命令执行或主动通讯能力。提示将日记、经验和图像明确视为不可信资料。仅向用户配置的模型服务发送所选资料及已采纳经验，不发送密钥作为文本、不读取其他账户资料。Authorization 仅在请求头中使用；远端地址必须 HTTPS；本机模型允许回环 HTTP；重定向禁用；超时 45 秒，并发最多 2 个整理任务。

默认不读取或传送截图。只有 `use_llm:true`、`include_images:true` 和后端视觉开关同时启用时才发送图像。按 [OpenAI 官方 Images and vision 文档](https://developers.openai.com/api/docs/guides/images-vision) 使用 `content` 数组中的 `text` 与 `image_url` 块、base64 data URL；每张图包含所属日记 ID 的文字说明。兼容服务仍需自行支持该协议。单次最多 8 张不重复附件、原始图片总计 8 MiB，文字快照最多 512 KiB，完整 JSON 请求最多 12 MiB。

模型测试使用本机 HTTP mock，未调用实际付费服务。测试覆盖持久化与权限、归档恢复、并发版本冲突、日记提前日期、图片伪装与截断、像素与大小限制、WebP 解码、经验采纳和回溯、视觉开关与默认隐私、严格模型输出、超时/取消、重定向阻断、失败保留历史、模型分析期间并发编辑的输入审计。
