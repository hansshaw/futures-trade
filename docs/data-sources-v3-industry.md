## 采集与质量约束

新增包 `backend/internal/industry`，接口为：

```go
c := industry.New()
observations, events, err := c.Liaoning(ctx)
observations, events, err = c.MOAFeed(ctx)
```

两源应分别维护启用状态、最后尝试、最后成功、最新资料日期和下次计划。默认间隔为 12 小时（最短 6 小时）；公开周报通常每周更新，不能因为今天没有新报告就标成故障，也不能因为连接成功就显示“实时”。跨节假日可延后发布；建议超过 14 天无新资料时提示检查新鲜度，并继续展示最后成功资料。

- 每次每源最多最新三期：一次列表加三次明细请求；请求间隔默认 250 毫秒，单请求超时 20 秒，响应最多 2 MiB。调用方应再设置整次任务截止时间。
- 只访问固定官方 HTTPS 主机及约定路径；列表中的外站、带凭据、带查询参数或片段的链接不进入请求。重定向也须同域且仍在白名单内。
- 使用标准 HTML DOM 解析，忽略脚本与样式文本；不运行网页脚本。严格核对标题、采集日期、样本范围、价格字段和单位。缺失值不转成 0，区间价不擅自取中点。
- 一个源所选三期中任一期失败，整次该源返回错误及空结果，不把部分成功伪装成源已更新。另一个源可独立运行。
- `observed_at` 表示实际监测日期；无时刻的日期以北京时间零点表示日期。事件 `published_at` 使用原页发布时间；只有日期时备注说明时刻未知。`available_at` 与事件 `ingested_at` 使用实际采集时间。
- 相同来源、报告、日期、指标及数值生成稳定 ID，重复采集由已有存储去重，并保留首次 `available_at`。来源修正数值会产生新记录；历史版本不被覆盖。数值变更事件也会获得不同 ID。
- 每条记录有真实来源 URL、统计口径备注，`is_demo=false`。普通周报事件标为低级别，不把统计发布自动描述为突发利多或利空。

本次实际 Go 网络验证共生成 **15 条观测、6 条事件**，运行约 3.42 秒；这些是当时的探测结果，不承诺远端持续可用或固定延迟。页面改版、停更与网络错误均需在接入面板显示。

## 到车量、淀粉价格和商业数据采购

Mysteel 官方说明提供 [Data Feed API](https://www.mysteel.net/products-services/data-products/)，覆盖包括农业在内的商品数据，并有 [农产品频道](https://ncp.mysteel.com/) 发布库存、消耗、开工和淀粉调查栏目。[官网服务报价](https://www.mysteel.com/fwbj.html) 描述的频道浏览和历史查看权益，不能据此推定包含 API、批量导出或向云端用户再分发权益。**某个山东到车量指标是否可通过 API 购买，本次未得到数据字典和合同确认。**

卓创官方 [数据定制页面](https://digital.sci99.com/channel/customized) 明确提供数据集成与标准数据接口服务。由此可以确认有正式 API 合作途径，但具体玉米到车、企业收购价、玉米淀粉价格的数据集、报价、更新频率和历史长度仍需供应商确认；没有现成凭据或合同就不实现猜测的私有 API。

建议采购前明确以下字段及权益，先提供脱敏样例和字段说明，再开发 adapter：

| 项目 | 必须明确的内容 |
|---|---|
| 到车口径 | 是门前排队存量、新到车辆、卸粮车辆，还是全天累计；统计时点、覆盖企业、是否含合同粮、车辆载重分布与节假日缺报规则 |
| 可比性 | 固定样本企业 ID、增减样本历史、同一地区不同来源是否可比；样本变化不得解释成真实需求突变 |
| 报价口径 | 企业/库点、年份、水分、容重、杂质、等级、含税/运费、干粮/潮粮、收购/入厂/出厂及生效时间 |
| 淀粉关联 | 玉米淀粉产地与等级、税运口径、库存、开工及副产品价格；淀粉期货价不能代替完整加工利润 |
| 历史与修订 | 首次发布时刻、修订时刻、版本、历史回补方式；供应商事后修订不得成为回测的事前信息 |
| 权益 | API 或文件交付、调用限频、缓存期限、历史下载、研究回测、云服务器部署、展示对象、再分发及 LLM 外发权限 |
| 费用与可靠性 | 数据集套餐和增项、账号/IP限制、停更通知、服务时限、失败重试与服务协议 |

后续接入应保留供应商原始指标 ID 与许可说明。`truck_arrivals` 仅在明确“辆”且测量口径匹配时使用；港口到货吨数、队列长度、成交量不自动换算成到车量。机器解析可使用标准 JSON/CSV 或正式 API，本版不抓取会员正文。

## 天气数据与产业解释

现有 Open-Meteo 采集器提供五个点位的三日降水和温度预报，属于前瞻模型数据，不是覆盖全省的站点实测。Open-Meteo 区分数据的 CC BY 4.0 许可与免费托管 API 的使用条件；免费 API 用于非商业评估，商业用途应根据其 [官方套餐和接口说明](https://open-meteo.com/en/pricing) 配置相应服务，不能把“数据开放”理解为免费端点不限用途。

下一步适合加入东北产区与山东加工区的区域权重、作物阶段、连续阴雨天数、收获后烘干条件和运输节点。天气影响必须按“播种/授粉/成熟/收获/储运”区分：同样的降雨量在不同阶段可能有相反含义。应保存每次预报的可用时间和目标时间，历史回测使用当时发布的预报版本，不能把后来观测或再分析数据当作当时已知的预报。正式气象预警与项目自定义阈值告警在 UI 中应分别标识。

## 量化使用与可视化

推荐显示每条序列的地区、实体、单位、价格类型、样本范围、监测日、发布日期与最后同步时间。辽宁元/吨与全国元/公斤可以在有标识的派生视图中换算，但原始存储保持原单位，也不能只换单位就把两者合并。

基础研究可比较同一口径的周环比、供需背景和价格传导的滞后关系。跨来源相关性、全国均价减期货价、工厂涨价与到车变化均只构成待检验假设。能够交易的基差还需合约月份、交割地点与质量、仓储、运输和时间成本的口径对齐。把多个地区均价直接减去主力价格，不能得出可执行套利收益。

当前采集只建立可追溯的观测与事件，不自动生成买卖指令，不宣称已经完成产业因子的历史验证。

## 验证方式

常规测试使用从真实页面提取的最小 HTML 表格/事实 fixture，不联网；包含日期、单位、范围、结构变化、失效链接、域名与重定向约束、响应大小、取消、单源部分失败及重复 ID 检查。真实探测需显式执行：

```bash
cd backend
go test -race ./internal/industry
go vet ./internal/industry
CORNWATCH_LIVE_INDUSTRY_TEST=1 go test ./internal/industry -run TestLiveOfficialSources -v
```

后续全量历史抓取、OCR、山东企业级数据、商业 API 与云端再分发均不在这两个适配器的既成能力中。
