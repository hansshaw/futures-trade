# 数据源请求频率、公开限制与本地保护

核验日期：2026-10-29，v0.6。以下区分来源公布的服务条件与本项目自行选择的刷新策略；没有公布数值额度的来源，不应从一次成功请求或网页刷新速度推导“允许每秒调用多少次”。

表中请求数不含重定向、手动操作、重启或失败后续轮次，不能作为服务商计费结算值。连续运行、没有额外操作时，天气约 120 次 HTTP 请求/日、30 天约 3,600 次；新浪按默认目标全天运行的理论上限约 172,800 轮/日，实际受网络耗时和退避影响。当前新浪调度没有按官方交易日历暂停夜间或节假日请求，因此不能按只有交易时段估算。

这些最小间隔约束自动采集配置。手动测试/同步允许在配置间隔内发起检查，但受下述按来源区分的成功缓存及 5 秒失败冷却保护；手动操作不应被外部循环当成绕过低频调度的接口。保护按当前进程内的数据源和连接生效，不是跨进程、跨账号、共享出口 IP 的全局配额管理器。后续云端多实例应集中调度、共享缓存和供应商配额，不能每个用户各运行一套公开源采集器。

## 已实现的保护与接口约定

`Definition.request_policy` 返回适合数据源页面展示的中文说明，包含已知的公开限制、本地自动频率及手动保护。数据源原有的间隔、许可、费用与新鲜度字段继续保留。

`Hub.Run(ctx, id, test)` 供手动连接测试/同步使用：

1. 同一来源正在执行时拒绝并发任务，返回 `ErrBusy`；HTTP 返回 429。不同来源保持独立。
2. 产业、天气等相同连接在成功获取并校验后的 5 秒内共用完整批次。行情成功缓存截止于原请求开始时刻加 min(配置间隔, 5秒)，500ms配置不会被原来的5秒缓存降为每分钟12次。“测试连接”后立即“同步”只获取一次上游数据；测试本身不写观测、事件或采集状态。
3. 缓存是获取/解析结果缓存，不是忽略校验的通道。端点或令牌变化后必须重新验证，旧连接的成功结果不能替新凭据背书。有效的“没有发布新场次”结果也可复用，普通空响应仍是错误。
4. 一次上游请求失败后，本地冷却 5 秒。此时再次测试/同步返回 `ErrCooldown`，HTTP 429 附 `Retry-After` 秒数，不重复请求上游、不增加失败计数、不改上次成功快照，也不移动自动退避截止时间。
5. 缓存不重写报价的 `observed_at`、`received_at`，也不重写观测/事件的 `available_at`。`LastAttempt` 和 `LastSuccess` 保留该批次原获取时刻，产业来源正常 `NextRun` 从原获取完成时刻计算，行情从原请求开始时刻加配置间隔计算；主力收盘证据也使用该时刻，不能通过稍晚点击同步把早先批次变成新的收盘确认。
6. `Outcome.cached=true` 和 `fetched_at` 明示复用及该批次获取完成时间。这里的获取时间指 Hub 中本次采集器调用完成；例如中储粮内部 60 秒缓存可能更早获取网络内容，原始记录的可用时间仍保留。成功/失败短时缓存不持久化，重启后重新建立。

`Hub.RunScheduled(ctx, id)` 供自动采集和报告生成共同使用，内部走相同采集、校验、缓存及入库路径。它只执行已启用、已配置、全局未暂停且 `NextRun` 已到期的数据源；否则返回 `Outcome.skipped=true`，不请求上游，也不改变时间、失败计数或已保存内容。报告可以读取已有快照，并同时记录数据时间、新鲜度及上次错误；“本报告已生成”不能被展示为“全部上游刚更新”。

调度资格判断与执行占用在同一把锁内完成，报告与自动轮询同时到期也只允许一个任务抓取。`Poll` 按最近待执行时刻在1至50毫秒内检查本地计划，不代表每秒请求来源。源失败后至少等待5秒，并采用指数退避，倍率最多 64；退避上限为“24 小时与配置间隔中的较大者”，确保本来配置 2～7 天的源不会因失败而反向增加请求。成功后的正常间隔完整保留，不再截短为 24 小时。采集失败继续保留上次成功数据。

当前盘面分析与日报还需要获取实际合约的公开日线，这条请求独立于 Hub 快照调度。两条分析路径共用 `marketdaily.Cached(marketdaily.New().Fetch)`：成功结果缓存 5 秒，同一键的并发请求只取一次，失败后冷却 5 秒。缓存键由规范化实际合约、北京时间日期和是否已到 15:15 组成，跨日或跨收盘确认边界必须重新获取，不能复用成熟度不同的结果。复用保持 `AvailableAt`、来源指纹及缺字段元信息，返回时复制日线与所有切片，调用方修改不会污染下一份报告。这同样是本地防重复策略，不是新浪批准的调用额度，也不提供历史行情可用性保证。

单个页面请求或报告任务取消时立即停止等待，但不会取消其他分析正在共用的日线获取。共享请求有独立的 20 秒总期限，底层 HTTP 客户端自身为 18 秒；采集函数必须遵守传入的 context。即使全部等待者退出，该次只读获取也最多继续至自身期限。日线缓存按当前进程生效，不能替代未来云端的集中配额和调度。

## 高频目标、计数与持久化

v0.6 新建行情配置默认0.5秒；升级时将仍使用旧默认新浪60秒/桥接10秒的配置迁移一次，用户已设置的其他间隔保留。界面可快捷设为120次/分钟，或者自行调低频率。低频产业数据不随行情一起加速。

每源最多一个请求进行中。调度采用开始到开始的目标间隔，慢请求不重叠、不累积欠账后突发追赶。最近一分钟计数记录真正发起的采集尝试（含失败，不含缓存命中）；统计起点单独返回，刚启动未满一分钟时不能把当前次数当作稳定速率。请求耗时是网络获取与解析总耗时，不是交易所到屏幕的延迟。

保存配置具有同源优先权：等待当前请求结束时，暂停该源的新请求，最多等待20秒；成功后按新配置继续或停用。其他来源不受影响。超时或用户请求取消时保留旧配置并解除等待状态，仍使用版本号防止覆盖他人的修改。界面允许采集进行中编辑和提交配置，不必抢占500毫秒间隙。

快速行情成功后即时更新内存并发送 `market` 事件；自动采集通常每5秒保存一次本地快照，手动同步、错误及主力状态转换会及时保存。`polling.persisted_at` 与 `persistence_note` 明示持久化状态，正常关闭等待任务并刷新末尾快照，异常退出可能丢失末尾尚未保存的几秒采样。源报价时间不会因保存、读取或重启变新。

每合约保留最近120个不同源时刻的实际采样，同一源时刻的新价格更新末尾点，不重复增加横轴时刻。这条短采样轨迹独立于历史日线/分钟K线；不聚合成声称完整的逐笔或分钟成交历史。MA/BOLL历史图表说明见[行情图表](market-chart.md)。

## 页面刷新、来源发布时间与实际延迟

`desktop/src/App.tsx` 的行情更新事件单独读取 `/api/market/live`，不会每500毫秒重新读取全部产业观测、日记或历史K线。其他资料保留15秒本地刷新及对应事件更新；数据源页读取本地状态。上述本地读取不调用外部采集器。市场面板的“同步”按钮调用数据源手动同步路径，历史图表按需获取并采用独立缓存。

需要分别看四个时间：

- **来源观测/统计时间**：例如期货报价时刻、企业晨间到车窗口、周报统计日。
- **发布时间**：来源什么时候公布该内容；可能晚于统计日。
- **首次获取/可用时间**：本系统什么时候真正得到该条数据；历史回测不能提前使用。
- **页面读取时间**：前端什么时候把已保存数据画到屏幕上。

把页面从 15 秒改为 1 秒只会增加本地读取；把周报检查从 12 小时改为 6 小时最多减少发现新公告的等待，不会得到实时收购价格。对来源实际延迟没有证据时只标记未知或依据原始时间判陈旧，不声称“500 毫秒实时成交”。天气展示预测目标日与获取批次；每小时抓取不等于上游天气模型每小时更新。进口玉米拍卖按日检查最近场次，不代表每天有成交，也不把当天没有公告记为零。

## 验证范围

`go test -race ./internal/datahub` 使用固定时钟、内存替身与本地测试服务验证：测试→同步只获取一次、缓存五秒边界、原时间与计划不被延长、主力收盘边界不被缓存跨越、令牌/端点变更必须重新获取、失败冷却 HTTP 429 和 `Retry-After`、报告尊重启用/暂停/到期/退避、并发请求互斥，以及重启后的计划和快照保留。测试不调用外网。

`go test -race ./internal/marketdaily` 另验证成功获取完成后的 5 秒边界、并发请求合并、单个等待者取消不影响其他调用者、共享请求超时、失败冷却与恢复、北京时间跨日/15:15 缓存隔离，以及源获取时间和所有可变切片的复制隔离。

这轮没有对公开网站做压测，也没有通过重复请求试探封禁阈值；官方条款和网页说明仅做低频阅读。供应商限流仍可能比本地策略严格，出现拒绝应保留已有数据并核实授权/服务状态，而非增加并发或更换身份继续请求。
