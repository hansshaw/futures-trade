# 从玉米盘面观察到可检验的交易研究

研究日期：2026-10-28（北京时间）。本轮在已有 Electron + React / Go 项目上补齐“观察 → 提出假设 → 计算风险 → 样本外检验 → 复盘修正”流程。以下区分市场知识、可检验假设和本次软件实现，不把技术指标或大模型解释当作已验证收益。数据源与开源架构比较继续见 [research.md](research.md)，既有撮合与账本边界见 [quant-model.md](quant-model.md)。

## 一、期货交易首先要看什么

期货价格对应的是特定品种、交割月份和合约规则，资金盈亏按合约名义敞口变化，保证金只是履约资金。账户权益、可用资金、保证金占用、持仓方向、到期月份必须一起看。结算、保证金、限仓和价格限制会影响可持有规模与退出能力；风险阈值不等于可保证的最大亏损。[证监会期货制度介绍](https://www.csrc.gov.cn/csrc/c100211/c1452111/content.shtml)、[CFTC 期货市场机制](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/economicpurpose.html)。

对于玉米，按“供给、需求、流通、预期、交易条件”五条线组织观察更便于形成可反驳的判断：

| 观察线 | 具体关注 | 如何连接价格 | 容易误判的地方 |
| --- | --- | --- | --- |
| 新季和存量供给 | 播种面积、单产、作物阶段、收获/售粮进度、库存、进口及储备投放 | 改变不同月份可供交付的数量和节奏 | 总产量增加不意味着每一天都有同等卖压；旧作库存与新作预期不能混成一条同比 |
| 饲用和深加工需求 | 饲料产量、生猪/禽类存栏、出栏体重、配方替代、淀粉开机率、加工利润 | 决定采购强度及企业补库能力 | 生猪价格上行不必然对应饲料需求上行；养殖利润、产能周期和配方替代存在不同滞后 |
| 流通与局部现货 | 企业同口径收购价、到车/卸车、港口集疏运、运价、区域库存 | 反映区域货源松紧和物流约束 | 到车量会受降雨、道路、排队、企业检修和统计时点影响；不能只用单厂一天数据代表全国 |
| 天气与政策事件 | 东北/华北分区、播种/授粉/灌浆/收获阶段、预报批次、进出口与收储公告 | 通过单产、质量、上市节奏、成本和预期传导 | 同一场雨在旱期与收获期作用不同；预报、实况和事后修订不能互换 |
| 可交易性 | 具体合约量仓、价差、盘口深度、买卖价差、涨跌停、距交割时间、保证金 | 决定信号能否用合理成本实现 | 主力连续只是研究序列；最后价不是保证成交价，换月也不是无成本更改代码 |

这些关系是待检验的传导路径。农业农村部的 [2026年10月 CASDE](https://scs.moa.gov.cn/jcyj/202610/t20261009_6488446.htm) 将玉米饲用消费与工业消费分列并分别调整，正好说明不能用一个关联品种价格替代完整需求判断。它采用当年10月至次年9月的玉米市场年度；后续供需库应按市场年度和发布版本组织，而不是按自然年直接连接。

现货“价格”必须带地区、主体、等级、水分、产年、税费、运输、结算方式、收购/到厂/平舱口径以及有效时刻。匹配后才能定义 `基差 = 可比现货价 − 对应期货价`。运费、质量和储存等因素会造成区域现货与期货差异。[CME 谷物基差和收敛说明](https://www.cmegroup.com/education/courses/introduction-to-grains-and-oilseeds/learn-about-grain-convergence)。项目当前的人工观察字段尚不足以证明每条报价可交割、可比较，因此本轮不把任意一条企业价减去主力期价展示成“可套利基差”。跨期或期现操作仍有基差、质量、融资、仓储、交割资格、两腿成交和流动性风险。[CFTC 基差风险定义](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/CFTCGlossary/index.htm)。

## 二、怎样读盘面，而不把指标当作结论

使用顺序建议是：确认合约和数据日期 → 判断价格结构和波动 → 看成交量/持仓量是否支持研究假设 → 对照期限结构与事件 → 明确失效条件及仓位 → 留存证据。先固定研究周期；日线工具适合日线状态研究，不能解释分钟盘口与逐笔订单流。

| 盘面问题 | 本轮提供的工具 | 合理用法和失效检查 |
| --- | --- | --- |
| 趋势还是过渡期 | OHLC、MA5/20/60、价格相对均线的排列 | 观察方向和回撤结构。均线是滞后平滑；横盘反复穿越时要考虑换手成本，不能把不同周期均线当成三份独立证据 |
| 波动是否扩大 | ATR14、ATR/收盘价 | 用相同单位比较止损距离和近期波幅；ATR不是最坏损失或未来波动上限 |
| 动量是否集中 | RSI14、MACD(12,26,9) | 描述相对涨跌强弱与均线差。RSI极值可伴随持续趋势，MACD金叉也可能滞后；不单独产生反转订单 |
| 是否突破旧区间 | 当前收盘与前20根日K高低区间 | 阈值排除当前K；收盘确认后的信号最早用于后续时刻。用当前高点计算“此前阻力”会把定义和结果混在一起 |
| 参与程度有无变化 | 日成交量、持仓量、较前日变化、当前量/此前20日均量 | 量与仓是不同概念。每份未平仓合约都有多空双方；无法由总量识别谁主动开仓或哪类参与者主导 |
| 不同月份如何定价 | 同日玉米期限结构、最近月减最远月价差 | 研究季节性、存储和供需预期；必须注明所比较合约，不把曲线斜率解释成确定预测 |

例如“价格上涨、持仓减少”仅是观察，可以提出“部分空仓回补”“跨期迁移”“双方离场后流动性改变”等候选解释，但总量本身无法在这些解释之间作出识别。成交量也不能单独证明买盘、卖盘或开平仓方向。[CME 成交量教学](https://www.cmegroup.com/education/courses/introduction-to-futures/what-is-volume)、[CME 持仓量定义](https://www.cmegroup.com/education/lessons/open-interest)。本轮界面和 API 的量仓标签明确写“仅现象，不能识别单边资金”。

期限结构有储存与季节性含义，但海外谷物市场的合约月份和交割条款不能照搬到大商所。[CME 谷物跨期与仓储说明](https://www.cmegroup.com/education/courses/understanding-futures-spreads/grain-intramarket-spreads-and-storage)。本轮只画同日、同模式、时间不晚于所选日K结束时刻的有效玉米合约，并明确价差取最近与最远交割月份；不进行跨期下单或价差回测。

## 三、把交易想法变成量化研究

量化的作用是把假设写成可重复执行的规则，并核对在当时可得信息、交易成本和资金约束下的结果。它不要求先上复杂机器学习，也不等于高频交易。玉米市场尤其需要结合季节性、跨月交割、产业链和信息发布时点。

| 研究族 | 示例假设（尚未证明有效） | 必须增加的检验 |
| --- | --- | --- |
| 时序趋势 | 价格在较长均线上方且突破历史区间时，后续收益分布有差异 | 单合约到连续策略的换月账本；横盘期成本、不同波动状态、参数邻域稳定性 |
| 均值回归 | 低波动区间里的偏离较容易回归 | 趋势破坏时的尾部损失；止损可成交性；不得见到测试结果后选“震荡区间” |
| 跨期/基差 | 可比现货、库存与期限结构共同刻画紧张程度 | 两腿同步、合约期限、交割资格、仓储和融资、保证金优惠的实际规则；不能假设无风险 |
| 产业链相对价值 | 淀粉加工利润、饲料替代关系与玉米预期变化有关 | 转化率、能耗、副产品、税费、品种乘数、生产周期与样本外协整稳定性；简单价格相减不等于利润 |
| 事件与天气 | 区域加权预报变化或企业调价扩散可能领先采购变化 | 首次发布时间/到达时间、事件去重、天气预报版本、传导时滞、无事件对照样本与多重检验 |

研究流程应固定为：先写经济机制和可观察的反证 → 冻结数据范围/时间规则 → 预先确定参数和成本 → 在训练历史开发 → 保留未来数据检验 → 以更高成本和极端路径压力检验 → 前向纸面记录 → 再评估模拟执行。时间序列不能随机打乱训练测试；存在重叠未来标签时还需要按标签跨度剔除边界泄漏，而不是机械加一个固定间隔。[scikit-learn 时间序列切分文档](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。本轮策略只使用过去收盘均线，没有拟合未来标签，因而采用连续时间留出及历史预热。

看结果时同时检查收益、最大回撤、完成往返次数、费用、滑点、期末未平仓、资金占用和不同状态下的分布。胜率不等于期望收益；低频单合约几十根日K不足以可靠估计稳定胜率、尾部风险或年化夏普。本轮保留原引擎不估计 Sharpe 的口径，不给未知统计量填0。

反复尝试参数后挑最高回测收益，会把噪声选成“规律”；一次时间留出也不能自动修复已经看过测试结果的调参。[Bailey 等，《The Probability of Backtest Overfitting》原论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。本轮不搜索最优参数，不声称完成滚动优化或统计显著性检验；以后需要实验登记、冻结测试集、新数据前向验证及对多次试验的控制。

必须持续防止的偏差包括：当前收盘产生同根开盘订单；今天的主力代码回填历史；复权连续价格被当成可交易价格；供应商修订值或天气实况回填历史；只收集“重要新闻”造成幸存者偏差；忘记两边费用、滑点和无法平仓；用毛盈利算胜率；只展示成功交易而不记无交易日；大模型利用训练中见过的后续历史。USDA 公开说明其作物进度数据存在后续修订，说明历史档案的“最新版”未必是当时可得版本。[USDA 作物进度报告修订政策](https://www.nass.usda.gov/Publications/Todays_Reports/reports/prog3625.pdf)。

## 四、代码审计发现的缺口与本轮补齐

原有项目已经具备单合约日线均线回测、次日开盘撮合、成本及基本风控，但缺少用户能直接解释的盘面研究、按权益反推风险手数、样本外对照、可留存截图的结构化复盘，以及从复盘中形成可追溯个人经验的流程。

| 缺口 | 本轮落地 | 仍未完成的部分 |
| --- | --- | --- |
| 价格曲线缺乏状态解释 | `research.Analyze` 输出 OHLC、量仓、均线、ATR/RSI/MACD、历史区间、谨慎解释和同期期限结构；前端可按契约展示 | 分钟/tick盘口、逐笔成交、量价分布、交易日历完整性校验、实时数据授权接入 |
| 固定手数难以理解风险 | `research.SizeRisk` 按全账户权益、止损距离及双边成本计算风险手数，再以保证金预算和开仓成本约束 | 已有组合/挂单净占用、相关品种合并风险、动态保证金、经纪商账户同步 |
| 全样本收益容易被误读 | `research.ValidateStrategy` 固定参数前70%训练/后30%测试、独立账户、训练历史只预热、测试双倍成本对照；返回参数/输入哈希/引擎版本 | 多个滚动窗口、参数敏感性、bootstrap/显著性、多策略实验登记、结果长期归档 |
| 日记和截图散落 | 复盘日期、合约、计划、假设、执行、反思、经验、情绪、纪律、盈亏和图片；搜索、归档、版本冲突检查 | 券商成交导入、订单与截图自动关联、组合归因、完整备份恢复操作流 |
| “AI学习”容易改写原始事实 | 从用户选定日记快照整理候选模式/待办/经验，保留证据ID、输入版本和指纹；经验需用户采纳后才进入后续上下文 | 对已采纳经验做长期效果检验、结构化交易数据验证、模型效果监测；没有对模型权重训练 |

复盘应记录当时看到的证据、原计划及失效条件，再记录实际行为和后果，区分“判断错误”“执行偏离”“正常随机损失”。盈亏由用户填写，不推断缺失交易或虚构绩效。规则整理可在没有大模型凭据时使用；模型分析只对选定文本和用户明确勾选的截图执行，截图默认不发送。截图里的文字、外部消息和模型输出均属于待验证内容。

本轮使用现有 Go 确定性核心，未新增大型量化运行时。处理低频研究的主要瓶颈在数据质量与执行假设；后续达到盘口执行阶段，再按实测延迟评估原生网关或独立执行进程，避免用语言速度掩盖信息延迟。

## 五、新指标、风险及验证的精确定义

### 日线指标

全部输入先通过已有 `quant.ValidateBars`，并要求单一玉米合约、单一演示/真实模式、时间和交易日严格递增。每个输出点只依赖自身及以前的K线；缺少样本用 JSON `null`，不回填未来信息。

| 字段 | 公式及初值 |
| --- | --- |
| `ma5/20/60` | 最近 N 个收盘的简单平均，含当前收盘；第 N 根首次有值 |
| `atr14` | TR为 `max(H−L, abs(H−前收盘), abs(L−前收盘))`；首根只有 `H−L`。前14个TR均值为初值，此后 `(13×前ATR+TR)/14` |
| `rsi14` | 前14次收盘变化的正/负变化均值播种Wilder平滑；第15根首次有值，RSI=`100×平均涨幅/(平均涨幅+平均跌幅)`；全平盘约定50，纯上涨100，纯下跌0 |
| `macd` | DIF=`EMA12−EMA26`；分别用首12/26个收盘SMA播种，后续alpha=`2/(N+1)`，第26根首次DIF |
| `macd_signal` | DEA为DIF的EMA9，以首9个DIF均值播种，第34根首次有值 |
| `macd_hist` | `2×(DIF−DEA)`；明确使用国内常见双倍柱口径，不能与未乘2的软件直接比较 |
| `prior_high20/prior_low20` | 当前之前20根日K的最高high/最低low，不含当前；第21根首次有值 |
| `volume_ratio20` | 当前成交量 / 当前之前20根日K平均量；基准量为0则空值 |
| `change_pct` | `(当前收盘/前一收盘−1)×100`，与按前结算价计算的终端涨跌幅不同 |
| `oi_change/oi_change_pct` | 与前一根持仓量之差及相对变化；前持仓为0时百分比为空 |
| `atr_pct` | `ATR14/当前收盘×100`，用于比较波幅尺度，不是尾部概率 |

趋势标签仅在60根齐备后按“价格>MA20>MA60”“价格<MA20<MA60”或交错分类。阈值和指标不是经优化选出的交易策略。未接交易日历意味着窗口按输入有效记录数计算，不能据此断言中间没有漏数据。

期限结构从 `allBars` 中选择同一 `trade_date`、同一 `is_demo`、`timestamp <= as_of` 的合法玉米日K；同合约同日取可见较晚记录，同结束时间冲突则排除该候选。所选主图合约使用已验证的主图末K。淀粉、生猪、过期或非法月份不混入。期限点可以包含尚在交割月内的合约，**不表示该合约仍允许当前账户交易**；当前仅按月份校验，尚无合约最后交易日与账户准入判断。价差为所有有效点中最近月减最远月，有效点不足两个返回空。

### 风险手数计划

本轮继承玉米乘数10吨/手、最小变动1元/吨，每tick每手10元。既有 [大商所玉米资料链接及核验记录](research.md) 有来源说明；本轮重新访问旧PDF超时，未据此刷新动态保证金、手续费或交易限额。用户输入应采用当前期货公司参数。

```text
风险预算 = 全账户权益 × risk_pct / 100
每手预计止损损失 = abs(计划入场 − 止损) × 10
                   + 2 × (每手每边手续费 + 每边滑点tick × 10)
风险手数 = floor(风险预算 / 每手预计止损损失)
每手保证金 = 计划入场 × 10 × margin_rate
保证金手数 = min(floor(权益 × max_margin_pct / 100 / 每手保证金),
                 floor(权益 / (每手保证金 + 每手开仓费用及滑点)))
计划手数 = min(风险手数, 保证金手数)
名义杠杆 = 计划手数 × 计划入场 × 10 / 全账户权益
```

多头止损必须低于入场，空头止损必须高于入场；价格需对齐tick。百分数字段 `risk_pct=1` 表示1%，`max_margin_pct=40` 表示40%；`margin_rate=0.12` 表示12%。不足1手返回0，不替用户缩小止损。止损是计划，不能保证跳空或涨跌停时按该价退出。当前模型只算独立计划；已有头寸、其他计划与挂单的预算不得重复使用。

独立手算验收：权益100,000元、入场2,200、止损2,180、风险1%、保证金率12%、占用上限40%、每边手续费1.2元/手、滑点1tick。每手损失222.4元、每手保证金2,640元，风险限4手、保证金限15手，所以计划4手；预计损失889.6元、保证金10,560元、名义金额88,000元、名义杠杆0.88倍。

### 时间切分与成本压力

至少80根日K，切分索引为 `floor(N×0.7)`，训练段需多于慢线窗口。训练和测试使用同一组预先给定参数及独立初始资金，训练段并未拟合参数。测试段使用新函数 `quant.BacktestFrom(config, bars, evaluationStart)`：评估前只更新均线，不成交、扣费、改变权益或触发风控。训练末日平仓尝试不影响测试账户；测试首日可以执行前一日收盘已确定的信号。两段各自末日尝试平仓，不能平仓时保留持仓并明确标注。

费用压力只对相同测试期重新运行：每边手续费和滑点tick同时乘2。若原配置为0，则该项仍为0，不伪造成本；用户应配置可信基准。成本变化可能提前触发风险停机、减少后续交易，所以压力收益不保证更低，需要同时比较交易次数和期末头寸。报告包含原配置、全输入SHA-256及引擎版本 `sma-daily-v2`，但当前API不自动持久化验证报告；需由调用端保存快照。

本次没有修改既有日线撮合边界：订单按下一开盘；日末成交量仍是事后可成交性过滤；收盘估值不等于真实结算资金账本；未模拟逐日结算、平今差异、盘口排队、盘中追加保证金和动态保证金。使用新接口不使这些假设变成真实交易。

## 六、验证与下一步顺序

单元测试采用手算序列而非仅对照实现本身：线性价格验证均线、ATR与MACD，交替涨跌验证Wilder RSI，单次冲击验证DIF/DEA/柱值；检查每个前缀不受未来影响；当前高低价不能移动自身历史突破阈值；同日/同模式/时点过滤阻断旧价、未来价、关联品种和冲突价。风险测试覆盖多空对称、双边费用、两个预算取小、正好边界、不足1手、开仓成本侵占保证金、非有限数和极小比率溢出。时间切分采用独立账本核验暖机不计交易/成本、训练损益不继承、训练不受测试行情影响、测试首日开盘不读当日收盘，以及末尾无法成交的披露。

在 `backend` 下执行：

```sh
go test -race ./internal/research ./internal/quant
go vet ./internal/research ./internal/quant
```

下一阶段优先顺序：

1. 获授权单合约日线/分钟数据和交易日历，保存首次到达时间、版本、缺失与过期状态；把企业报价规格、到车量样本和天气预报批次规范化。
2. 加入逐日结算与动态保证金、交割/限仓规则、真实换月双腿账本，开展多合约历史回放；独立框架交叉核对成交与权益。
3. 固化研究实验登记和多窗口前向评估，再加入可追溯事件因子、产业链和跨期组合；按真实供应商权限补采历史数据。
4. 接入模拟账户和订单回报，验证断线重连、撤单、重复消息、资金对账、停机及人工接管。交易风控保持确定性，不让大模型直接绕过账户约束。
5. 再评估真实交易与云端部署。程序化交易有现行规则和期货公司接入流程，需按届时有效要求核对。[证监会2025年第12号公告](https://www.csrc.gov.cn/csrc/c101954/c7564346/content.shtml)。桌面研究、真实交易和云端接入分别验收，不因回测通过而跳过执行验收。

这一顺序由实际缺口决定：先证明数据在当时可得、规则可复现、成本和资金正确，再讨论参数表现和执行速度。
