# 量化研究模型与验证记录

本文对应 `backend/internal/quant` 的当前实现，记录于 2026-10-28。它描述可复核的研究模型及边界，不是交易所撮合仿真、结算账单或可直接投入实盘的交易系统。演示行情是合成数据，不能据其回测收益判断策略有效性。

## 输入与策略范围

回测仅接受一个玉米合约代码 `cYYMM`，例如 `c2701`；月份限定现行玉米合约的1、3、5、7、9、11月，`c2702` 等偶数月代码无效。不能将主力连续指数、多个交割合约或复权连续价格当作同一个可成交合约。合约乘数固定为 10 吨/手、价格最小单位为 1 元/吨，因此 1 tick 为 10 元/手。当前没有历史合约规格版本、动态费用、交易所保证金表或客户类型交割资格规则。

`ValidateBars` 对导入批次支持多个玉米合约，按每个合约分别校验：

- 非空，单批最多 200,000 根；时间和显式 `trade_date` 严格递增，每个合约每天仅一根。
- 日K结束时间转换到 UTC+8 后，日期必须等于 `trade_date`。不把夜盘自然日直接当交易日。
- OHLC、结算价为有限正数且不超过 `1e9`；OHLC 对齐整数 tick，开收盘位于高低区间。结算价允许非整数。
- 成交量、持仓量为非负整数。涨跌停必须同时为零，或为有序的正整数价格；有价格限制时，OHLC 和结算价不得越界。
- 合约月份合法，记录不得晚于交割月；同一合约不能混合演示与非演示记录。回测额外要求所有记录与 `config.symbol`、`config.demo` 一致。

这里校验的是数据内部一致性，没有校验真实交易日历、上市首日、合约是否真实存在、价格限制是否符合当日交易所公告或原始提供方是否可靠。CSV 导入层另行拒绝明显未来时间；量化函数本身没有以当前墙上时间禁止研究调用。

参数须满足 `1 <= fast_window < slow_window <= 5000`，样本数大于慢线窗口；初始资金 `(0, 1e12]` 元，手数 `1..10000`，每手每边手续费 `0..1e6` 元，滑点 `0..10000` 个整数 tick，保证金率 `(0, 1]`，最大回撤阈值 `(0, 100]` 个百分点。参数不由引擎自动补默认值。

## 信号与执行顺序

策略是固定手数的双均线趋势持仓：当天收盘后计算包含当天收盘的快、慢简单均线，快线大于慢线目标做多，小于慢线目标做空，相等目标空仓。这不是只在交叉当天触发的一次性委托。预热完成之前不持仓，最早在第 `slow_window + 1` 根K线开盘执行。

每个日K按以下顺序处理：

1. 以当天开盘价估算已有持仓权益，检查跳空后的风控状态。
2. 在开盘价执行上一交易日收盘得出的目标。反向信号先平旧仓，再尝试开新仓，每一边独立计费并检查可成交性；旧仓平不掉就不能反开。
3. 若为研究区间最后一日，按事先约定的终止规则，尝试以收盘价平掉剩余持仓。
4. 按收盘价记录权益、持仓和日度回撤，再检查收盘风控。
5. 若没有触发停止交易状态，计算收盘信号，供下一根日K开盘执行。

开盘订单方向不使用当天或未来的收盘价。测试会改变当前和未来收盘，核对原开盘订单不变。但**整个撮合模型并非无未来信息的实盘执行模型**：日末总成交量用于下述事后过滤，研究终止日收盘价也作为预先约定的终止成交基准。

成交记录 `timestamp` 沿用所属日K的结束时间，不是交易所实际成交时间。`reason` 区分 `previous_close_sma_at_next_open`、`risk_liquidation_at_open` 和 `scheduled_end_of_test_close`；不能把标注为日K结束时间的开盘订单解释为收盘后才提交的订单。

## 可成交性与成本

每个交易日以日末总成交量作为可分配量。每次成功开或平 `lots` 手，扣减同日剩余量；剩余量不足则整笔拒绝，没有部分成交。零量日不能开仓、平仓或末日强平。该过滤只能说明历史日线不支持模型所假定的成交量，不能证明开盘当时有对应深度，也不能作为开盘前可获得的信号。当前未设置额外的最大市场参与率。

已知涨跌停时，拟买入价格达到涨停或拟卖出价格达到跌停，均保守拒绝成交，即便这天后来曾打开涨跌停。模型不会根据收盘后的高低价推断开盘排队能够成交。反方向成交仍需满足成交量条件。两项价格限制均为零表示未知，此时不实施限制判断，并在回测结果中警告。

成交 `price` 为观察到的开盘价或终止日收盘价，不人为改造成 OHLC 区间之外的价格。滑点独立折算为现金支出：

```text
每次成交手续费 = lots × fee_per_lot
每次成交滑点成本 = lots × slippage_ticks × 10 元
往返交易净收益 = 方向 × lots × 10 × (平仓价 − 开仓价)
                 − 开仓手续费 − 开仓滑点 − 平仓手续费 − 平仓滑点
方向：多仓 +1，空仓 −1
```

反向交易包含平仓、开仓两笔成交，因此收取两边成本；最后一次平仓同样计费。`total_slippage` 是已扣除现金成本的汇总，不应从 `final_equity` 再扣一遍。成交表单笔 `pnl` 是本次现金变动：开仓为负的本边成本，平仓为毛盈亏减本边成本；平仓行 `pnl` 不是完整往返的净收益，计算胜率时还会扣除已付的开仓成本。

资金和指标用 Go `float64` 计算，测试以 `1e-6` 元容差核对账本；这不是按分定点存储的券商账务系统。正式实盘账户模块应采用明确的金额精度及交易所费用舍入规则。

## 权益、保证金和风险

模型中的现金只随成本和已实现交易盈亏变动，权益为：

```text
权益(价格 P) = 现金 + 方向 × lots × 10 × (P − 开仓价)
研究保证金(价格 P) = abs(方向) × lots × P × 10 × margin_rate
```

保证金作为开仓资金约束，不作为永久损失扣除；开仓要求现金扣除本次手续费和滑点后足以覆盖保证金。固定手数，不会因保证金不足自动减仓开入较小手数。

`settlement` 当前仅参与输入校验，**不用于真实逐日结算**。净值曲线使用收盘价，未模拟结算价资金划转、每日已实现与未实现盈亏重置、盘中追保、平今差异手续费、动态保证金或资金利息。

每日开盘执行前和收盘检查：权益小于等于零、相对历史日末权益高点的回撤达到阈值，或持仓权益不足当前估计保证金，任一发生即永久停止本次回测的新增仓位。开盘触发可在同一开盘价尝试平仓；收盘触发通常在下一根开盘尝试平仓。反手平仓后及新开仓前，还会检查本次开仓成本是否将回撤推到阈值。

初始资金参与权益峰值。风控阈值不是损失上限；跳空、无法成交及仅检查开收盘都可能使损失超过阈值。即使风控要求平仓，仍不能绕过成交量与涨跌停条件。盘中峰值、谷值和追加保证金路径未重建。

末日平仓是研究终止规则，可发生在该日开盘开仓之后；模型仍累计该日每边成本及成交量消耗。末日无法平仓时，保留持仓和浮盈亏，明确返回警告：最终权益是未平仓按最后收盘估值的权益，尚未发生的退出手续费和滑点不扣除，不能标为完全平仓收益。

## 结果指标

| 字段 | 当前定义 |
| --- | --- |
| `initial_capital` | 配置中的初始权益，元 |
| `final_equity` | 最后一天估值后权益；若平仓成功包含全部已发生往返成本，未平则包括浮动盈亏 |
| `total_return_pct` | `(final_equity / initial_capital − 1) × 100`，不年化 |
| `max_drawdown_pct` | 日末净值相对于初始资金及此前日末高点的最大百分比回撤；不是盘中最大回撤 |
| `total_fees` / `total_slippage` | 所有已成功成交边的手续费 / 现金滑点成本 |
| `trade_count` | 已完成的往返交易数，不是成交记录行数 |
| `win_rate_pct` | 净收益大于 `1e-8` 元的已平往返数 / 全部已平往返数；零收益不算胜利；没有已平往返时为0占位并警告 |
| `open_position` | 期末有符号手数；多仓正、空仓负 |
| `unrealized_pnl` | 期末持仓相对开仓价的毛浮动盈亏，不含未来退出成本 |
| `sharpe_ratio` | 当前不估计，JSON 省略该字段，不把缺值伪装为零 |
| `equity_curve[].position` | 该日日末有符号手数；最后一天成功终止平仓后为零 |

## 主力合约研究规则

`ResolveMain(bars, asOf)` 独立于回测成交模型，只生成研究主力判断，不能声称是交易所官方主力标识。它从头顺序重建历史，不把今天的主力代码回填到历史，且不自动生成跨合约交易或连续收益。

时点与数据处理：

- 只使用 `timestamp <= asOf` 且 `trade_date` 不晚于 `asOf` 的上海日期的有效玉米日K。无效日K会被跳过；可见数据混合演示和非演示时拒绝计算。
- 按交易日标签分组排序。同一合约同日多条仅保留结束时间较晚的可见记录，不把重复记录计成多个确认日；正常导入层已经禁止同日冲突。
- 从当日候选集中排除交割月及更早月份，以及成交量或持仓量为零的合约。没有根据自然日推算假交易日。
- 这里的“连续两个交易日”精确含义是输入中相邻两个有效交易日标签。若某个真实开市日所有合约的数据完全缺失，仅凭本模型不能区分停市与漏数；正式数据管道需要交易日历和完整性检查。

首次确认要求同一日至少有两个可比较候选。候选按成交量降序、持仓量降序、交割月升序排列；第一名还必须没有别的候选持仓量更高，且不能存在成交量和持仓量完全相同的并列领先者。相同候选在两个相邻数据交易日满足条件后，才确认初始主力。

已有主力时，换月候选必须是比曾确认的最远交割月还远的合约，并同时满足：

```text
候选成交量 > 原主力当日成交量 × 1.1
候选持仓量 > 原主力当日持仓量 × 1.1
```

两个条件都是严格大于，恰好达到 110% 不够。多个候选满足时使用上述排序中靠前的候选。相同候选连续两个数据交易日满足后换月；切换后不能回切到更近月。没有合格候选、候选变化或当日缺少原主力有效量仓数据时，原待确认计数重置。缺原主力数据时可保留过去已确认的主力，但不据此新确认换月。

当前合约进入交割月就清空该当前选择，保留 `previous_symbol`；远月数据不足时不会仅因日历月份变化强行选出远月。重新确认仍需足够的比较数据。`confirmation_days` 表示当前 `pending_symbol` 的进度；确认完成时 pending 清空、进度重置为0，`required_days` 始终为2。

输出前另按 `asOf` 检查：历史已确认或待确认合约若此时已进入交割月则清空。尚未到交割月的旧判断不会因自然日间隔自动失效；`reason` 披露最近可用交易日，最新日期缺主力数据时另作说明。应用必须结合此日期判断数据陈旧程度，不能把 `as_of=现在` 理解为价格已更新至现在。

`asOf` 目前约束K线结束时间，未维护每个行情版本的历史可获得时间。晚导入的历史数据、供应商修订数据是否在历史时点已经可知，不能仅由当前 `Bar` 结构证明。库中已入库的同键数据不可被静默覆盖，但这还不等于完整的时点可得数据集；未来事件因子回测还需 `available_at`、修订版本及特征快照。

## 独立账本与关键验证

手工核算基准 `TestIndependentThreeLotShortLedger`：初始100,000元，收盘序列1200、1100、1000、900；快线1、慢线2。第3天以1000开空3手，第4天终止时以900平空。每手每边手续费2.5元，滑点2 tick。

| 项目 | 手工结果 |
| --- | ---: |
| 毛收益 | `3 × 10 × (1000 − 900) = 3000` 元 |
| 每边手续费 | `3 × 2.5 = 7.5` 元 |
| 每边滑点 | `3 × 2 × 10 = 60` 元 |
| 开仓现金变动 | −67.5 元 |
| 开仓日末权益 | 99,932.5 元 |
| 平仓现金变动 | 2932.5 元 |
| 手续费合计 / 滑点合计 | 15 元 / 120 元 |
| 最终权益 / 总收益率 | 102,865 元 / 2.865% |
| 最大日末回撤 | 0.0675% |
| 已平往返 / 净收益胜率 | 1 / 100% |

其他测试覆盖下一开盘成交时点、改变当日/未来收盘不改变已确定开盘订单、反手每边成本、毛赚但净亏不计胜利、开盘跳空风控、保证金不足、零量、涨停买入、末尾跌停无法平仓、同日总成交量预算、未知涨跌停警告、非法数值/OHLC/时间/合约以及演示模式混用。主力测试覆盖初始数据不足、重复日不重复计数、严格时点、阈值双条件、缺失中断、远月防回切、交割月及陈旧待确认。

验证命令在 `backend` 目录运行，均通过：

```sh
go test -race ./internal/quant
go vet ./internal/quant
go test ./internal/quant -run '^$' -bench . -benchmem
```

## 本机微基准

记录日期：2026-10-28（Asia/Shanghai）；环境为 Linux amd64、Go `go1.27.3`、13th Gen Intel Core i5-13400。Go 输出的基准后缀为 `-16`；测试循环本身串行，不能把该后缀当成16个并发回测任务。

| 基准 | 输入与实际路径 | 测得均值 | 内存 / 分配 |
| --- | --- | ---: | ---: |
| `BenchmarkBacktest` | 240根非平坦、有效的合成玉米日K；均线5/20、双边费用、实际开平仓及权益输出，包含输入JSON序列化与SHA-256指纹 | 362,370 ns/op，约0.362 ms/次 | 102,150 B/op，498 allocs/op |
| `BenchmarkResolveMain` | 1200个观测交易日、每天6个交割合约，共7200根合成日K；量仓随交割距离变化，重建初次确认与多次换月 | 8,495,199 ns/op，约8.50 ms/次 | 3,156,337 B/op，36,025 allocs/op |

数据生成和基准前验证在计时区间外；回测基准计入调用中的输入校验、结果构建和随机结果ID，不含HTTP、数据库、行情采集、Electron渲染、网络时延或大模型调用。输入是测试生成器数据，不是经核验的历史市场样本。这是单次本机微基准结果，不是端到端延迟指标、实时吞吐承诺或实盘低延迟适配证明。


## v0.2 研究扩展

`BacktestFrom(config,bars,evaluationStart)` 支持评估前只做均线预热；账户从评估首日空仓启动，之前的价格不产生费用、成交或权益。`Backtest` 等价于起点0，既有账本口径保持一致。版本标记更新为 `sma-daily-v2`，报告返回输入指纹和评估起点。固定参数70/30检验、双倍费用与滑点、指标定义及风险手数公式见 [新增研究模型](trading-research.md#五新指标风险及验证的精确定义)。
