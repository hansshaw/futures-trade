# CornWatch · 玉米市场研究工作台

面向中国玉米期货的 **Electron 桌面应用 + Go 后端**。当前版本 **v0.2** 已实现信息归集、事件分析、日线盘面研究、风险手数计算、时间留出检验，以及支持截图与 AI 整理的每日复盘。深入需求分析、市场知识与缺口评估见 [期货交易研究方案](docs/trading-research.md)。完整路线和开源项目比较见 [架构方案](docs/architecture.md)、[资料与来源核验](docs/research.md)。原有 `codex-harness-analysis.html` 保留。

**默认展示合成演示数据，未接入实时期货行情，没有下单接口。** `c2701` 是初始关注合约；程序按历史量仓数据判定研究主力，不根据月份写死，也不声称核实了当前真实主力。演示收益不能作为策略有效性的证据。

## 启动桌面

要求 Node.js 22.12+、npm、Go 1.25+；本机已用 Node 26 / Go 1.27 验证。首次安装 Electron 需下载对应平台运行时。Linux 需要图形桌面及 Electron 常规运行库。

```bash
npm ci
npm run build
npm start
```

开发模式：

```bash
npm run dev
```

`dev` 启动 Vite、Electron 及独立 Go 子进程；`start` 使用构建好的界面。Electron 后端使用随机回环端口和会话令牌，关闭应用时终止子进程。前端没有 Node 权限，启用 sandbox 和 context isolation；API Key 不传给渲染层。不要通过关闭 Chromium 沙箱解决日常启动问题。

数据库保存在 Electron 的 `app.getPath('userData')/cornwatch.db`，Linux 通常为 `~/.config/cornwatch/cornwatch.db`，实际路径取决于系统与打包名称。独立服务默认使用工作目录下的 `data/cornwatch.db`，两者相互独立。复盘正文、截图、智能体报告和输入快照位于同目录 `cornwatch.db.journal.db`，桌面未保存草稿位于 `journal-drafts.json`。退出应用后同时复制这三个文件进行本地备份；不要在运行时直接复制正在写入的文件，不要多进程共用同一库。

## 导入历史数据

在「数据与设置 → 导入行情 CSV」选择 UTF-8 文件，注明真实来源。表头模板是 [samples/bars-template.csv](samples/bars-template.csv)，不附带冒充历史行情的合成价格。

```text
symbol,timestamp,trade_date,open,high,low,close,settlement,volume,open_interest,limit_up,limit_down
```

- `symbol` 是真实玉米合约，例如 `c2701`；不接受主力连续代码。`timestamp` 是日 K 结束时间，采用含时区的 RFC3339，如 `2026-09-01T15:00:00+08:00`。
- `trade_date` 是来源提供的交易日 `YYYY-MM-DD`。日 K 结束时间须落在该上海日期；这不是对夜盘 tick 自然日的映射规则。
- OHLC 为元/吨，符合玉米最小跳动 1 元；成交量和持仓量为非负整数。结算价单独保留。
- 填写实际历史涨跌停价格；确实缺失时两列同时填 `0`，回测会披露限制。保证金和费用仍为本次研究的固定参数，不能视为历史真实费率表。
- 文件内每个合约的时间和交易日必须递增；整批校验成功才写入。相同数据重复导入无副作用；同一合约同日的冲突记录拒绝覆盖。
- 桌面一次最多 10 MiB。样本和导入数据位于独立存储空间；请勿把虚构数据导入为真实历史数据。新版本更正/修订数据集工作流尚未实现。

导入后将图表与回测的来源切换为「导入日线」。只有一个合约的数据不足以确认市场主力，仍可用于该合约的基准回测。

## 天气、行业信息与定时采集

「采集产区天气」实际调用 Open-Meteo，采集哈尔滨、长春、沈阳、潍坊、郑州五个点位的三天降水和温度预报。点位不代表全省，也不是气象部门预警。`observed_at` 是目标日期，`available_at` 是采集时间，二者不可互换。降水预报达到 25 mm 时生成研究关注事件。数据署名：[Open-Meteo](https://open-meteo.com/)，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。免费服务适用于非商业评估；商业用途应按 [服务说明](https://open-meteo.com/en/pricing) 调整端点与授权。

收购价和到车量没有在此预置未经核验的万能免费源。可以先录入可追溯的企业报价和同口径调查，或配置有采集和存储权限的 RSS/Atom：

```bash
export CORNWATCH_FEED_URLS='https://your-authorized-provider.example/feed.xml'
export CORNWATCH_POLL_INTERVAL='5m'
export CORNWATCH_WEATHER_ENABLED='true'
npm start
```

上面的域名是占位符，需替换。Feed 按配置间隔采集（最短一分钟）；天气自动任务至多每小时成功采集一次。默认不开启任何后台外部采集。无有效发布时间的 Feed 条目拒绝入库；修订文本产生不同 ID，保留证据。尚未实现跨来源事件聚类、采集失败指数退避和断点补采。

## 配置大模型

通过支持 Chat Completions JSON 模式的服务接入，也可使用本地兼容模型。模型名由你配置，不固定某家供应商。

```bash
export LLM_BASE_URL='https://your-model-provider.example/v1'
export LLM_MODEL='your-model-id'
export LLM_API_KEY='your-secret'
npm start
```

`LLM_BASE_URL` 是不含 `/chat/completions` 的基础地址。远程服务要求 HTTPS；本地回环模型可用 HTTP。配置模板见 [.env.example](.env.example)；程序**不会自动加载 `.env`**，请通过终端、IDE 或服务管理器注入变量，避免把凭据写入源码。

点击事件里的「大模型分析」才把该事件的标题、正文、来源、地区、发布时间与演示标识发给配置的服务。无配置时仍可运行明确标为 `rules-v1` 的规则摘要。模型输出经过字段、方向、置信度范围和逐条原文引用校验；幻觉引用、截断、网络失败都不会覆盖已保存分析。分析版本含模型/提示词版本与完成时间，模型不能访问交易接口或执行任意工具。复盘智能体使用同一配置；文字整理发送所选日记和最近30条已采纳经验（可关闭）。只有设置 `LLM_VISION_ENABLED=true` 且每次勾选发送截图，才会传输图像；单次最多8张、原始图片合计8MiB。模型输出保存独立报告和输入快照，不改写原始日记。经验需手动采纳，可撤回，供后续检索而非训练模型权重。LLM 分析没有在本次交付中使用真实付费账户验证，兼容服务是否支持 JSON 模式需实际确认。

## 每日使用流程

1. 在「盘面研究」选择合约和数据，查看量价持仓、波动与同期跨月结构；点击K线选择研究日期，左右键可微调。
2. 写下经济机制、入场条件和失效条件，再用风险计算器检查资金约束。预填参数只是示例，需要按账户和期货公司实际规则调整。
3. 点击「记录复盘」带入当日数值；「截图存入复盘」同时保存本应用当前可见图表。历史截图可能含选择日期之后的行情，日记会注明，不能当作历史可知证据。
4. 在「复盘日记」补充计划、执行和盘后反思，可粘贴/拖入截图。Ctrl/⌘ S 保存；切换工作区保留草稿，桌面重启从独立草稿文件恢复。归档可恢复。
5. 进入「复盘智能体」选已保存记录，先用规则检查完整性或用大模型整理；核对模式与来源，再采纳候选经验。发现不适用时撤回；历史输入快照仍保留。
6. 在「回测实验室」运行基线及时间切分检验，导出检验JSON保存参数、输入哈希与引擎版本。该检验不自动拟合参数，不是完整滚动前向验证。

截图单张最多4MiB/2400万像素、每篇6张；支持PNG/JPEG/WebP。图片从日记移除后仍留在本地库，确保历史报告可追溯；存储采用文件权限保护，没有数据库加密。未提供实盘成交对账，自记盈亏不作为核验绩效。

## 回测口径与边界

当前策略是**链路验证基线**，不是已证明有效的玉米交易策略。详细账本、规则和基准见 [量化模型说明](docs/quant-model.md)。

- 短均线高于长均线做多，低于做空，相等目标空仓；信号从收盘产生，最早下一条日线开盘执行。
- 合约乘数固定 10 吨/手、每 tick 为 1 元/吨。手续费是每手每边；滑点单独折为现金成本，不会重复从成交价与资金扣除。
- 成交价按观察到的开/收盘价，**日终成交量用于事后可成交性过滤**；仅信号隔离了未来价格，撮合不能声称等同实盘。
- 净值按收盘估值，结算价目前用于输入校验；没有模拟真实逐日结算、盘中追加保证金、开盘盘口深度、部分成交或平今费差异。
- 终止日尝试收盘平仓；无法成交时保留未平仓位、浮盈亏与明确警告，不虚构平仓。没有计算年化 Sharpe。
- 不支持跨合约拼接获利、事件因子回测、多合约组合、换月订单、完整交易日历、walk-forward 或自动参数优化。这些已列入后续验收路线。

历史新闻、天气再分析和今天生成的 LLM 结论不能直接当作历史可知信息。当前事件 `available_at` 由首次入库时间确定；原文修订与模型完成时间保留，但尚未接入策略特征。回测结果保存参数、不可覆盖的数据、输入指纹和引擎版本。

## 验证与打包

Windows x64 安装包在 [GitHub Releases](https://github.com/hansshaw/futures-trade/releases) 下载，文件名为 `CornWatch-<版本>-windows-x64-setup.exe`。安装向导支持选择目录，并创建桌面及开始菜单快捷方式；安装后无需单独安装 Node.js 或 Go。发行包暂未进行代码签名。

在 Windows 上自行构建安装包：

```powershell
npm ci
npm run package:win
```

输出位于 `release/`。手动运行 `Windows installer` 工作流可在 Windows 上测试、构建并验证安装后的桌面功能；工作流不自动发布 Release。卸载默认保留用户数据。

```bash
cd backend
go test -race ./...
go vet ./...
go test ./internal/quant -run '^$' -bench . -benchmem
cd ..
npm run build
python3 scripts/smoke.py
node scripts/electron-smoke.mjs
npm run package
```

`smoke.py` 使用临时数据库验证鉴权、导入事务、重复记录、事件分析、回测成本和重启持久化，结束后删除测试数据。`electron-smoke.mjs` 在 Linux 图形会话中启动实际 Electron，使用临时用户目录验证页面交互，并将截图写入 `artifacts/`；不关闭沙箱。打包命令默认生成当前平台的应用目录到 `release/`；本轮已用独立输出 `release/v0.2/linux-unpacked/cornwatch` 保留旧版。关闭旧窗口后可运行新版，或在仓库根目录执行 `npm start`。跨平台发布还需要在目标系统构建、安装验收与签名。验证记录见 [docs/validation.md](docs/validation.md)。

## 后端单独运行与云迁移

```bash
go -C backend run ./cmd/cornwatch --addr 127.0.0.1:8765 --data data/cornwatch.db --ui ../desktop/dist
```

也可在仓库根目录运行已构建的 `./bin/cornwatch`。开发浏览器 UI 可另开终端 `npm run dev:web`；其 `/api` 代理到 `127.0.0.1:8765`。若独立后端配置了 `CORNWATCH_TOKEN`，Vite 进程需继承相同变量。

提供 [Dockerfile](Dockerfile) 作为无桌面的后端构建起点，默认不种演示数据。非回环监听要求至少 32 字符的 `CORNWATCH_TOKEN`。现有 Electron 只管理本机子进程；远程服务配置、TLS、用户登录/权限、限流、持久任务队列和多实例存储仍属于云化阶段。本轮没有发布服务到公网。

后续顺序：**接入授权行情/产业数据 → 多年时点数据、真实结算和换月账本 → 多窗口样本外及成本压力检验 → 模拟交易/恢复对账 → 满足接入要求后的受控实盘**。程序化交易接入要求和公开资料来源均在研究文档中列出。
